# 长期记忆地基

## 背景

当前项目有 `messages` 和 `checkins`，但缺少独立长期记忆层。成熟 Agent 需要把短期对话、业务记录、用户偏好/目标分开，否则上下文会无限膨胀，也难以解释某条“个性化”来自哪里。

## 方案

- 新增 `memories` 表：
  - `user_id`：用户隔离。
  - `thread_id`：可选来源会话。
  - `kind`：记忆类型，第一阶段支持 `preference`。
  - `content`：记忆内容。
  - `importance`：排序权重。
  - `source`：写入来源。
- 新增 `/api/memories`：
  - `GET`：按当前用户列出记忆，可按 kind 过滤。
  - `POST`：显式创建记忆，若带 thread_id 则校验归属。
- ChatService 增加保守写入策略：
  - 仅当用户显式说“记住/以后请记得/我的目标/我的偏好/我喜欢/我不喜欢”时写入。
  - 不做隐式画像推断。

## 方案反思

- 当前只完成长期记忆写入与查询地基，还没有把记忆检索注入 Agent prompt。
- 显式规则避免隐私误判，但召回率有限；后续可增加用户确认后的 LLM 提取。
- 后续需要去重、编辑、删除、向量检索和来源解释。
