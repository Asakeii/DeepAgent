# 分层记忆策略

## 背景

长期记忆地基已经具备 `memories` 表、显式写入、API 查询和上下文注入，但记忆类型仍偏单一，容易把用户偏好、目标、长期事实、业务记录和历史事件混在一起。成熟 Agent 需要让记忆来源和使用边界更清晰，否则上下文会变成不可解释的杂糅提示词。

## 目标

- 标准化长期记忆层：`preference`、`goal`、`fact`、`business`、`episodic`。
- 显式记忆写入时根据内容做保守分类。
- 注入 Agent 上下文时按层展示，帮助模型区分偏好、目标、事实、业务记录和历史事件。
- 保持无状态设计：记忆仍从 MySQL 读取，不引入进程内缓存。

## 非目标

- 不引入向量库、embedding 检索或自动摘要。
- 不从普通对话中隐式推断用户画像。
- 不让长期记忆覆盖系统指令、开发者指令、安全策略或本轮用户要求。

## 方案反思

- Eino 提供图编排、checkpoint/interrupt 和 retriever 等框架能力，但应用级用户记忆的分类与治理仍属于产品层职责，本阶段复用现有 `memories.kind` 字段完成。
- 规则分类可解释、低风险，但召回率有限；后续可以在用户确认后接 LLM 结构化提取。
- 目前检索仍按层级、重要度和更新时间排序，尚未做到 query-aware；这比过早引入复杂向量链路更适合当前阶段。
