# 用户设置持久化

## 背景

成熟 Agent 产品需要允许用户保存默认语言、时区和运行偏好。当前运行参数主要来自请求体或全局配置，无法表达用户级偏好，也不利于后续设置页、多模型路由、成本预算和个性化控制。

## 目标

- 新增 `user_settings` 表，将用户设置持久化到 MySQL。
- 新增 `/api/settings` 查询与更新接口，沿用当前用户解析边界。
- ChatService 在运行前读取用户设置，作为请求未显式指定时的默认值。
- 保持无状态多 Pod：设置不保存在进程内缓存，任意 Pod 都从共享数据库读取。

## 非目标

- 不实现完整账号系统、OAuth 或 JWT。
- 不实现前端设置页。
- 不在本阶段做多模型路由、成本预算或团队级配置。

## 方案反思

- 本阶段使用 typed columns 而不是 JSON，便于校验、迁移和直接参与运行默认值。
- `auto_accept_plan` 已持久化，但由于现有 `ChatRequest.auto_accepted_plan` 是非指针 bool，无法可靠区分“未传”和“显式 false”，因此暂不自动覆盖运行请求，避免破坏现有前端行为。
- 后续如果要完整消费布尔型默认值，应把请求 DTO 调整为 pointer bool 或引入明确的 settings merge 层。
