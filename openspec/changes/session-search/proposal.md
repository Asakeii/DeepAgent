# 前端会话搜索

## 背景

历史会话已经按用户隔离并展示在侧边栏，但只能按最近活动浏览。真实使用中会话数量增长后，用户需要按标题、thread id 或消息内容快速定位历史 run。

## 目标

- `/api/sessions` 支持 `q` 查询参数。
- 后端搜索仍按当前用户隔离。
- 前端侧边栏提供搜索输入，并展示空搜索结果状态。

## 非目标

- 不引入全文搜索引擎。
- 不做高亮、分页或复杂排序。
- 不改变消息读取和 thread ownership 规则。

## 方案反思

- 当前使用 MySQL `LIKE` 和 `EXISTS` 查询，足够支撑轻量工作台；如果历史数据量增大，应演进到全文索引或专用搜索服务。
- 搜索在后端完成，而不是只做前端本地过滤，避免用户只能搜到当前已加载的 50 条。
